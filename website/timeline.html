Phase 1: Reconnaissance

T1087.002 · T1046

Reconnaissance happens in four steps. First, an nmap scan maps the network and identifies BANK-DC01 by its open ports. Seeing ports 88 (Kerberos), 389 (LDAP), and 445 (SMB) confirms this is a Domain Controller. Next, Kerbrute queries the Kerberos service to validate which usernames actually exist — no credentials needed. Those valid usernames feed a password spray, which tries one common weak password across every account without triggering lockout. It hits on jsmith. Finally, with real credentials, NetExec dumps the full user list — revealing svc_backup as the Kerberoasting target in Phase 3.

Phase 2: Brute Force Attack

T1110 — Brute Force

The brute_force_sim.ps1 script runs from BANK-WS01 using the DirectoryServices API, making 10 consecutive failed authentication attempts against oakridgebank\jsmith. After 5 failures, the account lockout policy fires — generating Event ID 4740 on the Domain Controller.

code brute_force_sim.ps1 — run from BANK-WS01 
# brute_force_sim.ps1
# Lab: OakridgeBank AD Authentication Attack Lab
# Target: oakridgebank\jsmith  |  Technique: T1110

$domain   = "oakridgebank.local"
$username = "jsmith"
$badPasswords = @(
    "wrongpass1", "wrongpass2", "wrongpass3",
    "wrongpass4", "wrongpass5", "wrongpass6",
    "wrongpass7", "wrongpass8", "wrongpass9", "wrongpass10"
)

Write-Host "[*] Starting brute force simulation against $username@$domain"
Write-Host "[*] $(Get-Date -Format 'HH:mm:ss') - Attack begins"

foreach ($pwd in $badPasswords) {
    $secPwd = ConvertTo-SecureString $pwd -AsPlainText -Force
    $cred   = New-Object System.Management.Automation.PSCredential("$domain\$username", $secPwd)
    try {
        $null = [System.DirectoryServices.AccountManagement.PrincipalContext]::new(
            [System.DirectoryServices.AccountManagement.ContextType]::Domain, $domain
        ).ValidateCredentials($username, $pwd)
    } catch {}
    Write-Host "[-] Failed attempt with password: $pwd at $(Get-Date -Format 'HH:mm:ss')"
    Start-Sleep -Milliseconds 500
}
Write-Host "[*] Simulation complete. Check BANK-DC01 event log for 4625, 4771, and 4740."

Phase 3: Kerberoasting

T1558.003 — Kerberoasting

Using a valid domain user account, the attacker requests a Kerberos service ticket (TGS) for any account with a registered Service Principal Name. The ticket is encrypted with the service account's password hash. It can then be exported and cracked offline without generating additional network traffic.

Phase 4: Privilege Escalation

T1078 — Valid Accounts

Using the cracked service account credentials, the attacker authenticates from BANK-KALI and abuses AD group permissions to add themselves to a privileged security group. This fires Event ID 4728 — the clearest forensic evidence of privilege escalation in an AD environment.
