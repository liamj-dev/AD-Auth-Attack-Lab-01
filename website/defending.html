Module 03

Defense in Depth

No single control stops every attack. Effective AD security layers multiple defenses: enforce logging, limit blast radius with account lockout, centralize logs via WEF, and correlate with a SIEM. All four were deployed and validated in this lab.

The Four Pillars Deployed in This Lab

Audit Policy

check_circle ENFORCED

Advanced audit policies ensure authentication events are captured. Without logging, attacks are invisible.

auditpol /set /subcategory:"Logon" \
  /success:enable /failure:enable

auditpol /set /subcategory:"Kerberos Authentication Service" \
  /success:enable /failure:enable

auditpol /set /subcategory:"Credential Validation" \
  /success:enable /failure:enable
Screenshot: auditpol output

Account Lockout

check_circle ACTIVE

Locks accounts after 5 failed attempts for 15 minutes. Stops brute force — any attack triggering this fires Event ID 4740.

Set-ADDefaultDomainPasswordPolicy `
  -Identity "oakridgebank.local" `
  -LockoutThreshold 5 `
  -LockoutObservationWindow 00:30:00 `
  -LockoutDuration 00:15:00 `
  -MinPasswordLength 12 `
  -ComplexityEnabled $true
Screenshot: lockout policy — threshold=5

Windows Event Forwarding

check_circle ROUTING

Source-initiated WEF subscription forwards Security, Sysmon, System, and Application logs from BANK-WS01 to BANK-DC01 as the collector.

<!-- subscription.xml (excerpt) -->
<QueryList>
  <Query Id="0" Path="Security">
    <Select Path="Security">
      *[System[EventID=4624 or
        EventID=4625 or EventID=4740]]
    </Select>
  </Query>
</QueryList>
Collector: BANK-DC01 · Forwarder: BANK-WS01

Wazuh SIEM

check_circle MONITORING

Wazuh 4.14 on BANK-SIEM01 ingests logs from both agents. Three custom rules detect brute force, privilege escalation, and Kerberoasting in real time.

# local_rules.xml (excerpt)
<rule id="100001" level="12">
  <if_matched_sid>60122</if_matched_sid>
  <frequency>5</frequency>
  <timeframe>300</timeframe>
  <description>Brute Force Detected</description>
  <mitre><id>T1110</id></mitre>
</rule>

Custom Wazuh Detection Rules

All three rules were validated end-to-end — attacks executed, alerts fired, active response triggered.

Rule ID: 100001 Level 12 · HIGH

Brute Force Detected

5+ failed logon events (4625) from same source within 300 seconds. Active response: firewall-drop on attacker IP for 300s.

if_matched_sid: 60122 · frequency: 5 · timeframe: 300
MITRE T1110 — Brute Force
Rule ID: 100002 Level 14 · CRITICAL

Privileged Group Change

User added to privileged security group (Event ID 4728). Indicates privilege escalation or unauthorized admin access.

if_sid: 60159 · eventID: 4728
MITRE T1078 — Valid Accounts
Rule ID: 100003 Level 14 · CRITICAL

Kerberoasting Attempt

Event ID 4769 with ticket encryption type 0x17 (RC4). RC4 is weak and commonly requested during Kerberoasting to enable offline cracking.

eventID: 4769 · ticketEncryptionType: 0x17
MITRE T1558.003 — Kerberoasting
